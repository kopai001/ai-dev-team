# System Requirement — Module: โปรโมชัน (Promotion)

## FR-PRM-001: สร้างและจัดการโปรโมชัน
- รองรับ 2 ประเภทโปร: ส่วนลด, โปรชุด
- กำหนดช่วงวันที่มีผล, สาขาที่ใช้ได้, กลุ่มลูกค้า
- เปิด/ปิดโปรโมชันได้ทันที
- แก้ไขโปรได้เฉพาะก่อนมีการใช้งาน (หลังมีใช้ต้องสร้างใหม่)

## FR-PRM-002: สร้างโปรชุด (Bundle)
- เลือกสินค้าหลายรายการพร้อมจำนวน
- กำหนดราคาชุด (แจ้งเตือนถ้าราคาชุดสูงกว่าผลรวม)
- ระบบตรึงราคาชุดแม้ราคาสินค้าเดี่ยวจะเปลี่ยน

## FR-PRM-003: ระบบใช้โปรอัตโนมัติ
- ตรวจสอบโปรที่ match กับออเดอร์อัตโนมัติขณะขาย
- แนะนำโปรที่ประหยัดสุดให้ลูกค้า
- ใช้โปรอัตโนมัติโดยไม่ต้องกดเพิ่ม (configurable)
- แสดงรายการส่วนลดในบิลแยกชัดเจน

## FR-PRM-004: ตั้งค่าการ Stack โปร
- กำหนดได้ว่าโปรแต่ละอันใช้ร่วมกับโปรอื่นได้หรือไม่
- เมื่อมีหลายโปร match พร้อมกัน ระบบเลือกโปรที่ให้ส่วนลดสูงสุดก่อนเสมอ (auto priority ตามมูลค่าส่วนลดที่คำนวณได้)

## FR-PRM-005: วิเคราะห์ตะกร้าสินค้า
- ระบบวิเคราะห์ product affinity จากประวัติบิล
- แสดงคู่สินค้าที่ซื้อพร้อมกันบ่อย + สถิติ
- สร้างโปรชุดจากผลวิเคราะห์ได้โดยตรง
- ขณะขาย: แนะนำสินค้าที่หากซื้อเพิ่มจะ match โปรชุดกับสินค้าที่เลือกไว้แล้วในตะกร้า (แสดงสินค้าที่ขาดของโปรชุดที่ใกล้ครบ)

## FR-PRM-006: สถิติการใช้โปรโมชัน
- ดูจำนวนครั้งที่ใช้โปรแต่ละอัน
- ดูส่วนลดรวมที่ให้ไปต่อโปร
- เปรียบเทียบยอดขายก่อน/หลังใช้โปร

---

## Non-Functional Requirements

### Performance
- ตรวจสอบและคำนวณโปรอัตโนมัติภายใน 100ms

### Permission
| Action | เจ้าของ | แอดมิน | พนักงาน |
|--------|---------|--------|---------|
| สร้าง/แก้ไขโปร | ✓ | ✓ | ✗ |
| เปิด/ปิดโปร | ✓ | ✓ | ✗ |
| ดูโปรโมชัน | ✓ | ✓ | ✓ |
| ดูสถิติ | ✓ | ✓ | ✗ |
| วิเคราะห์ตะกร้า | ✓ | ✗ | ✗ |

### Validation
- โปรชุดต้องมีสินค้าอย่างน้อย 2 รายการ
- ส่วนลด % ต้องอยู่ระหว่าง 0-100
- วันสิ้นสุดต้องหลังวันเริ่ม
