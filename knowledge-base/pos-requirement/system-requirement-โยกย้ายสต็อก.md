# System Requirement — Module: โยกย้ายสต็อก

## FR-TRF-001: สร้างรายการโยกย้าย
- ระบบต้องรองรับการสร้างรายการโยกย้ายสต็อกระหว่างสาขา และระหว่างสาขากับคลังกลาง
- เลือกต้นทางและปลายทางได้จาก dropdown สาขาทั้งหมด
- เพิ่มสินค้าได้หลายรายการในรายการโยกย้ายเดียว
- แสดงสต็อกต้นทางปัจจุบันขณะเพิ่มสินค้า
- แจ้งเตือน (ไม่บล็อก) เมื่อจำนวนขอโอนเกินสต็อกต้นทาง

## FR-TRF-002: ขออนุมัติ
- บันทึกรายการเป็น draft ก่อนส่งคำขอได้
- ส่งคำขออนุมัติ → แจ้งเตือนแอดมินทันที
- แสดงสถานะ "รออนุมัติ" จนกว่าแอดมินจะตอบ
- ผู้ขอดูสถานะรายการของตัวเองได้

## FR-TRF-003: อนุมัติ / ปฏิเสธ (แอดมิน)
- แอดมินรับแจ้งเตือนและดูรายละเอียดคำขอได้
- อนุมัติทั้งหมดหรืออนุมัติบางรายการ (ลดจำนวน) ได้
- ปฏิเสธต้องระบุเหตุผล
- เมื่ออนุมัติ: ตัดสต็อกต้นทางทันที + เปลี่ยนสถานะเป็น "รอรับ"
- แจ้งสาขาปลายทางอัตโนมัติ

## FR-TRF-004: รับสินค้าที่ปลายทาง
- สาขาปลายทางรับแจ้งเตือน "มีสินค้ามาถึง"
- กรอกจำนวนที่รับจริงต่อรายการ (อาจต่างจากที่อนุมัติ)
- แนบรูปหลักฐานได้ (ไม่บังคับ)
- ยืนยันรับ → สต็อกปลายทางเพิ่ม
- ส่วนต่าง (shortage) บันทึกและแจ้งแอดมิน

## FR-TRF-005: ดูประวัติโยกย้าย
- ค้นหาและกรองรายการโยกย้ายด้วย: สถานะ, ต้นทาง, ปลายทาง, ช่วงวันที่
- ดูรายละเอียดแต่ละรายการ (สินค้า, จำนวนขอ/อนุมัติ/รับจริง)
- Export รายการโยกย้ายเป็นไฟล์

## Non-Functional Requirements

### Performance
- โหลดรายการรอการอนุมัติภายใน 1 วินาที
- การอนุมัติและตัดสต็อกต้องสำเร็จแบบ atomic (ไม่มีสถานะกึ่งกลาง)

### Permission
| Action | เจ้าของ | แอดมิน | พนักงาน |
|--------|---------|--------|---------|
| สร้างคำขอ | ✓ (ทุกสาขา) | ✓ (ทุกสาขา) | ✓ (เฉพาะสาขาตัวเอง) |
| อนุมัติ/ปฏิเสธ | ✓ (ทุกสาขา) | ✓ (ทุกสาขา) | ✗ |
| รับสินค้าปลายทาง | ✓ (ทุกสาขา) | ✓ (ทุกสาขา) | ✓ (เฉพาะสาขาตัวเอง) |
| ดูประวัติทั้งหมด | ✓ (ทุกสาขา) | ✓ (ทุกสาขา) | ✗ |

### Notification
- แอดมินทุกคนรับแจ้งเตือนทันทีเมื่อมีคำขอใหม่
- สาขาปลายทางรับแจ้งเตือนทันทีเมื่ออนุมัติ
- ผู้ขอรับแจ้งเตือนเมื่อถูกอนุมัติ/ปฏิเสธ

### Data Integrity
- การตัดสต็อกและการเพิ่มสต็อกต้อง atomic
- ถ้า transaction ล้มเหลว ต้อง rollback ทั้งคู่
- ทุก movement ต้องมี StockMovement record
