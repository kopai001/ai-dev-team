# System Requirement — Module: สต็อก

## FR-STK-001: ดูสต็อกสินค้า

- **โครงสร้าง:** 1 Branch = 1 stock location (สาขาปกติ และ คลังกลาง ใช้กลไกเดียวกัน; คลังกลางคือ Branch type=warehouse ที่ไม่ผูกกับสาขาปกติ)
- แสดงยอดสต็อกคงเหลือ ราย Branch และรวมทุก Branch
- แสดงสถานะสต็อกด้วยสีสัญลักษณ์: ปกติ (เขียว), ต่ำ (เหลือง), หมด (แดง), ใกล้หมดอายุ (ส้ม), หมดอายุแล้ว (แดงเข้ม)
- กรองสต็อกตาม: หมวดหมู่, Branch, type (สาขา/คลังกลาง), สถานะ
- แสดง "เฉพาะที่ต้องเติม" (สต็อกต่ำกว่าขั้นต่ำ)
- เปรียบเทียบสต็อกระหว่าง Branch ในตารางเดียว
- ขยายดูรายการ StockLot ต่อสินค้าได้ (lot_no, expiry_date, qty ต่อล็อต ต่อ Branch)

## FR-STK-002: รับสินค้าเข้าสต็อก

- รับสินค้าได้หลายรายการพร้อมกันในใบรับเดียว
- ระบุจำนวนที่รับได้ทั้งในหน่วยฐานและหน่วยซ้อน
- กรอกวันหมดอายุต่อรายการ (ไม่บังคับ)
- บันทึกราคาทุนต่อรายการ (อัปเดต cost price อัตโนมัติ)
- ระบุจำนวนเสียหาย (ไม่นับเข้าสต็อก แต่บันทึกไว้)
- ระบบสร้าง StockLot อัตโนมัติเมื่อยืนยันใบรับ (1 lot ต่อ product+expiry_date)
- ประวัติการรับสืบค้นได้ย้อนหลัง พร้อม lot_no

## FR-STK-003: ขั้นต่ำสต็อกและแจ้งเตือน

- ตั้งค่าขั้นต่ำสต็อกต่อสินค้าต่อ Branch ได้ (รวมคลังกลาง)
- ระบบตรวจสอบและแจ้งเตือนสต็อกต่ำอัตโนมัติ
- แสดง badge แจ้งเตือนบน icon สต็อกเมื่อมีสินค้าต่ำกว่าขั้นต่ำ
- รายการ "ต้องเติม" เรียงตามความเร่งด่วน

## FR-STK-004: วันหมดอายุและ Auto-Expire

- ระบบ background job รันทุกวันเที่ยงคืน
- ตรวจ `StockLot.expiry_date < today AND status = active` → เปลี่ยน status เป็น `expired` อัตโนมัติ
- แจ้งเตือนแอดมินและเจ้าของรายชื่อล็อตที่หมดอายุวันนี้ (lot_no, product, qty รวม, ราย Branch)
- แจ้งเตือนล่วงหน้าตามจำนวนวันที่ตั้งค่า (default 7 วัน)
- แสดงรายการ "ใกล้หมดอายุ" แยกต่างหาก จัดเรียงตาม expiry_date ใกล้ก่อน
- สินค้าหมดอายุแสดงสีแดงเข้ม ไม่บล็อกการขาย (แต่แจ้งเตือน)

## FR-STK-005: ขอตัดสต็อก (Adjustment Request)

- พนักงานส่งคำขอตัดสต็อกพร้อมเหตุผล
- สามารถระบุล็อตที่ต้องการตัดได้ (override FEFO) หรือปล่อยให้ระบบเลือก FEFO
- แอดมินทุกคนรับแจ้งเตือนคำขอรอการอนุมัติ
- แอดมินอนุมัติหรือปฏิเสธพร้อมระบุเหตุผล
- เมื่ออนุมัติ: ตัดจาก StockLotBalance (FEFO) + StockBalance ลด + StockMovement บันทึก

## FR-STK-006: ประวัติความเคลื่อนไหวสต็อก

- แสดงประวัติทุก StockMovement ของสินค้าแต่ละชิ้น
- กรองตาม: ประเภท movement, ช่วงวันที่, สาขา, lot_no
- แสดง: วันเวลา, ประเภท, จำนวน, ผู้ดำเนินการ, อ้างอิง (บิล/ใบรับ), lot_no
- StockMovement เป็น immutable — ไม่มีการแก้ไขหรือลบ

## FR-STK-007: สุขภาพสต็อก (Stock Health)

- แสดง dashboard สุขภาพสต็อกรวม: % สต็อกปกติ, ต่ำ, หมด
- แจ้งเตือนสินค้าที่หมดเร็วกว่าปกติ (velocity anomaly)
- แสดงสินค้าขายดีที่ควรสต็อกเผื่อเสมอ

## FR-STK-008: นับสต็อก (Stock Count)

- สร้างรายการนับสต็อกต่อ Branch ได้ (1 รายการต่อ 1 Branch — สาขาปกติ หรือ คลังกลาง ใช้กลไกเดียวกัน)
- **เลือกสินค้าที่จะนับได้** — ไม่จำเป็นต้องนับทุกสินค้า; เลือกทีละรายการหรือเลือกตามหมวดหมู่
- ระบบ snapshot ยอด system_qty รวม (ทุกล็อต) ต่อสินค้าที่เลือก ณ เวลาเริ่มนับ
- พนักงานกรอก counted_qty รวม ต่อสินค้า (ไม่แยกล็อต)
- ระบบยังทำธุรกรรมปกติได้ระหว่างนับ — ไม่ lock
- ระบบคำนวณ difference = counted_qty - system_qty อัตโนมัติ
- รายการที่มี difference ≠ 0 สร้าง StockAdjustment อัตโนมัติ (reason_type = count_variance) รอแอดมินอนุมัติ
- **เมื่ออนุมัติ**: ล็อตเก่าทั้งหมดใน Branch zeroed out + สร้าง StockLot ใหม่ 1 lot ด้วย counted_qty (ไม่มี expiry_date)
- บันทึก StockMovement type=count_adjustment เมื่ออนุมัติ
- ดูประวัติการนับสต็อกย้อนหลังได้ พร้อม difference และผู้รับผิดชอบ

## FR-STK-009: StockLot / FEFO / FIFO

- ระบบแสดงรายการล็อตต่อสินค้าต่อ Branch (lot_no, expiry_date, qty, status)
- สินค้าที่ `has_expiry_date = true`: ตัดสต็อก **FEFO** — lot expiry_date ใกล้สุดก่อน
- สินค้าที่ `has_expiry_date = false`: ตัดสต็อก **FIFO** — lot received_date เก่าสุดก่อน
- พนักงาน/แอดมินระบุ lot_id ตรงๆ ได้เพื่อ override FEFO/FIFO
- แสดงเตือนเมื่อ lot ที่เลือก override ไม่ใช่ lot ที่ระบบจะเลือก (เตือน ไม่ block)
- ล็อต status=expired ยังตัดสต็อกได้ผ่าน Adjustment (reason_type=expired)

## Non-Functional Requirements

### Performance

- โหลดหน้าสต็อกทั้งหมดภายใน 2 วินาที
- อัปเดตยอดสต็อก real-time เมื่อมีการขาย/รับ
- Background job auto-expire ต้องเสร็จก่อน 00:30 น.

### Data Integrity

- การเปลี่ยนสต็อกทุกครั้งต้องมี StockMovement record
- ห้ามแก้ไขหรือลบ StockMovement ที่บันทึกแล้ว (immutable)
- `StockBalance.quantity` ต้องสอดคล้องกับ Σ `StockLotBalance.quantity` เสมอ (enforce ด้วย DB transaction)
- สต็อกติดลบได้เฉพาะเมื่อตั้งค่า `allow_negative_stock = true`

### Alert & Notification

- Push notification เมื่อสต็อกต่ำกว่าขั้นต่ำ (แจ้งแอดมินและเจ้าของ)
- Push notification เมื่อล็อตหมดอายุ (แจ้งแอดมินและเจ้าของ พร้อมรายชื่อล็อต)
- Push notification ล็อตใกล้หมดอายุ (แจ้งล่วงหน้าตามที่ตั้งค่า)
- Daily summary รายการสต็อกวิกฤต (เช้าวันใหม่)
